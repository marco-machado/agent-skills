# Web Search Methodology for Research

This guide provides search methodology for the web search step in the research skill. Read this before executing searches to improve coverage and result quality.

## Query Generation

When given a research topic, generate 3-5 search query variations:

- **Exact names**: use product/project names, brand names, official terminology
- **Synonyms and alternatives**: how different audiences describe the same thing (e.g. "vector database" vs "embedding store" vs "similarity search engine")
- **Technical terms**: include version numbers, protocol names, standard identifiers where relevant
- **Comparative queries**: "X vs Y", "X alternatives", "best X for Y"
- **Recency-focused**: append year or "latest" to catch recent developments

## Source Prioritization

Search systematically across these source tiers:

**Tier 1 — Authoritative**
- Official documentation and project websites
- Peer-reviewed papers (Google Scholar, arXiv, Semantic Scholar)
- Established tech publications (official blogs, release announcements)

**Tier 2 — Community validated**
- GitHub repositories and discussions
- Stack Overflow / Stack Exchange
- Reddit (subreddit-specific, check upvotes and recency)
- Hacker News discussions

**Tier 3 — Supplementary**
- Technical blog posts (Dev.to, Medium — verify author credibility)
- Conference talks and presentations
- Comparison sites and aggregators
- Non-English tech communities (CSDN, Juejin, Zhihu) for items with strong presence in those ecosystems

## Information Gathering Standards

- **Look beyond page 1** — valuable information is often buried in later results
- **Check dates** — note publication dates; flag anything older than 12 months as potentially outdated
- **Cross-reference** — verify claims across multiple sources before including
- **Note conflicts** — if sources disagree, include both perspectives with attribution
- **Version awareness** — check if information applies to current versions or has been superseded
- **Distinguish official from community** — official docs vs. community workarounds vs. unverified suggestions

## Output Quality Checklist

Before returning results, verify:
- [ ] Multiple query variations were tried
- [ ] Sources span at least 2 tiers
- [ ] All items include source URLs
- [ ] Dates are noted for time-sensitive information
- [ ] Conflicting information is flagged
- [ ] No duplicate items (different names for the same thing)

## When Results Are Thin

If searches return insufficient results:
1. State what was searched and what was found
2. Note which query variations produced no results
3. Suggest the topic may be too niche, too new, or need different terminology
4. Recommend specific communities or forums where the user could ask directly
